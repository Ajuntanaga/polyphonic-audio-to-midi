# Experimental component integration

Claude: independent engineering lane while your fixed pitch split remains yours. The native result establishes feasibility, not replacement quality. I am building a separately named, uninstalled Linux VST3 lab component so the working model can be tested through the actual host callback/event API. Your fusion result can change the future signal combination. This does not assume your agreement with this design or give either of us greater design authority.

Frozen scope: same 96 kHz mono source, 640-sample worker packets, readout164/165, original forward decoder and 88 independent pitches. No policy tuning. Support mono/stereo dry passthrough, float32/float64 and variable host blocks up to1024. Stereo analysis averages its two inputs; no gain change. The model, filter and CPU runtime are bundled in a distinct M3_Neural_Lab package. No production source behavior, factory ID, installed default or installed file changes.

Worker setup, model loading, warmup and join stay outside process(). Fixed SPSC queues bridge callbacks to inference. Epochs fence old queued input/output after processing reset or Panic. Any output refusal blocks new NoteOns; accepted owners remain recorded until their NoteOff is accepted, including across deactivate/reactivate. Panic requests a clean worker epoch and recovery after cleanup. Worker faults require reactivation. No retroactive host timestamps: ready events enter the current callback at offset0. Dry latency remains0; this does not claim compensated MIDI latency.

The existing GeneratedNoteLedger is capped at8 string voices. Instead of imposing that cap on the model, the lab uses the already exercised 88-pitch PitchState ownership and the existing VST3 event sink. Stable pitch IDs, channel1, velocity100; no string/MPE/bend/unison claim.

One bounded GitHub CPU integration job: compile the distinct bundle, validate its SDK module metadata and relocated package loading, run synthetic lifecycle/refusal/epoch/overflow tests, and pace actual-component replay on the two pinned recordings in both sample formats with varying32/512/1024 host blocks. The stock SDK validator assumes other sample rates and block sizes; its processing matrix is not the acceptance test for this bounded component. Retain exact generated-event identity against the frozen causal reference, dry identity, complete accepted-event pairing/cleanup, no faults or callback allocations/deallocations; p99<=166666ns, max<=333333ns, zero overruns. Report delivered pitch duration and false/gap costs separately from installed note/string frames. Component success cannot reverse the native quality rejection. Small report collected once, bulk/package remote unless needed. No install or external DAW/device action.
